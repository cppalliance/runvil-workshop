# build-workshop

- The crate has two modes. The build mode builds Workshop with Cargo. The `bundle` mode builds one platform's Tauri bundle and ends at Tauri's bundle directory, `target/<triple>/release/bundle/<nsis|macos|appimage>`, which it prints. Nothing here builds an installer: the installers are built from that bundle in `cppalliance/runvil`, which holds the Qt IFW definition, the install tests, and the release workflow.
- Nothing here compiles the Gateway: it is the release `gateway-pin/pin.json` names, from `--gateway-binary`, `RUNVIL_GATEWAY_SIDECAR`, or the file `tools/fetch-gateway-sidecar.mjs` stages (`gateway_source` in `src/main/sidecar.rs`). A staged Gateway is never removed; only a named one staged for a Windows build is.
- Workshop bundles the Gateway as a sidecar only for Windows targets (`bundles_sidecar` in `src/main/sidecar.rs`). Only `crates/workshop/desktop/tauri.windows.conf.json` declares `externalBin`, and the config agreement test in `src/main/tests/config.rs` holds the two in step.
- The names of Workshop's Plugin directory are the constants in `src/main/plugin.rs`, which must equal those `crates/workshop/gateway-discovery/src/peer.rs` searches; a test in `src/main/tests/plugin.rs` compares the two.
